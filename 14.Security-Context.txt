Security-Context [security settings and privileges]
---------------------------------------------------
There are two levels of SecurityContext:
1. Pod-level SecurityContext – applies to all containers in a Pod (unless overridden at container level).
2. Container-level SecurityContext – applies only to a specific container.

Remember these 5 important hardening settings:
1. runAsNonRoot: true
2. allowPrivilegeEscalation: false
3. readOnlyRootFilesystem: true
4. capabilities: drop: [ALL]
5. seccompProfile: type: RuntimeDefault

privileged: true allows a container to run in privileged mode, giving it capabilities similar to the host machine's root user.
allowPrivilegeEscalation: false → Don't allow processes to gain additional privileges.

root@controlplane:~$ k run pod --image=busybox --command -o yaml --dry-run=client > pod.yml -- sh -c 'sleep 1d'
root@controlplane:~$ ls
filesystem  pod.yml
root@controlplane:~$ cat pod.yml 
apiVersion: v1
kind: Pod
metadata:
  labels:
    run: pod
  name: pod
spec:
  containers:
  - command:
    - sh
    - -c
    - sleep 1d
    image: busybox
    name: pod
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}

pod/pod created
root@controlplane:~$ k get po

/ # exit
