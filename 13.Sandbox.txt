CRI -- Container Runtime Interface
----------------------------------
Note: gvisor will slow Node Performance, make sure you install gvisor only required node.

Kubernetes + containerd: kubelet → CRI → containerd → containerd-shim → runc → Linux kernel → Create Container
Kubernetes + CRI-O: kubelet → CRI → CRI-O → runc/crun → Linux kernel → Create Container
Docker: Docker CLI → dockerd → containerd → containerd-shim → runc → Linux kernel → Create Container
Podman: Podman CLI → libpod → runc/crun → Linux kernel → Create Container

Kata Containers and gVisor provide additional isolation between container workloads and the host.
Three important technologies:
- runc – Standard OCI runtime.
- Kata Containers – Hardware virtualization-based isolation.
- gVisor – User-space application kernel-based isolation.
         - user-space kernal for contianers

root@controlplane:~$ cat run.yml 
apiVersion: node.k8s.io/v1
kind: RuntimeClass
metadata:
  name: gvisor 
handler: runsc
root@controlplane:~$ k apply -f run.yml

root@controlplane:~$ k get runtimeclasses.node.k8s.io 
NAME     HANDLER   AGE
gvisor   runsc     4s

root@controlplane:~$ k run gvisor --image=nginx -o yaml --dry-run=client > gvisor.yml
root@controlplane:~$ vi gvisor.yml 
root@controlplane:~$ cat gvisor.yml 
apiVersion: v1
kind: Pod
metadata:
  labels:
    run: gvisor
  name: gvisor
spec:
  runtimeClassName: gvisor
  containers:
  - image: nginx
    name: gvisor
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
root@controlplane:~$ k apply -f gvisor.yml 
pod/gvisor created
